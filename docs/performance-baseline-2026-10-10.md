# 后置长文基准（v0.16.240）

按功能和桌面体验先行的顺序，完成相应验证后执行 `npm run benchmark:long-doc`。环境为当前无头 Linux、系统 Chromium、Vite 开发服务器、单工作进程；纯文本载荷分别为 1/5/10 MiB。不是 Typora 对比，也不代表真实 Mac、混合媒体或生产包表现。

修复原基准输入验证：载荷尾部已有 x，改为输入原文不存在的 Z，确认真实输入已显示后计时。检测到属性解析对非属性正文也进行全文换行规范化和分行；改为快速检查顶部标记，仅解析 YAML 头部。需要正文的导出仍保持正文换行规范化，偏移检测不构造正文副本。

| 阶段   | 载荷  | 打开    | 末尾单字符输入 | 20 帧滚动 |
| ------ | ----- | ------- | -------------- | --------- |
| 优化前 | 1 MB  | 1127 ms | 87 ms          | 326 ms    |
| 优化前 | 5 MB  | 3569 ms | 183 ms         | 1087 ms   |
| 优化前 | 10 MB | 6674 ms | 346 ms         | 1134 ms   |
| 优化后 | 1 MB  | 1202 ms | 72 ms          | 309 ms    |
| 优化后 | 5 MB  | 3630 ms | 157 ms         | 1083 ms   |
| 优化后 | 10 MB | 6686 ms | 300 ms         | 920 ms    |

两阶段各一次，不足以断言统计显著改善。两个阶段均 3 项通过，输入和滚动完成。10 MB 打开仍约 6.7 秒，后续性能重点是实际设备重复采样及混合媒体，不以本轮结果认定与 Typora 等速。

生产构建仍有大块提示（应用入口及部分 Mermaid 预构建图表模块）；图表与公式按需加载已经存在。本轮没有通过提高告警阈值掩盖提示，也没有为了分块改写第三方图表实现。此项保留为 P3，后续结合生产包启动和资源加载指标决定分包策略。
