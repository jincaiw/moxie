# 第六轮：目录刷新误阻止退出（2026-10-11）

## L15 原因与修复

上一轮观察的“保留恢复副本并关闭”未退出，已在旧 QA 包重新复现。实际 CUA AX 返回“正在执行文件操作，请完成后再关闭。”，未保存内容继续保留。确认框关闭后窗口获得焦点，会触发 useFolder 的只读目录刷新；原退出检查使用 folderBusy，把此刷新与文件修改混在一起，因而取消退出。

现改为检查真实保存、文件修改和拖入复制的 in-flight ref。只读目录刷新不阻止恢复副本写入和退出；原有写入期间文档变化、存储失败、保存取消及主进程多窗口握手检查继续保留。没有修改应用主进程退出逻辑。

新增确定性回归让目录刷新 Promise 一直挂起，再触发 focus/keep-close，确认恢复副本写入成功、发送 ready；另一用例让真实保存挂起，确认发送 cancel、恢复编辑。专项首次失败是用例按钮写成“打开文件夹…”而实际为“打开文件夹”，日志保留；修正选择器后 5 项专项与完整回归通过。
