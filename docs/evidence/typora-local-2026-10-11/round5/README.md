# 第五轮：废纸篓、恢复与路径别名（2026-10-11）

## 实机发现 L14

第四轮自建 `readonly-copy.md` 经原生另存为后使用 `/var/...` 路径，侧栏按 `/private/var/...` 枚举。同一文档移入废纸篓后，侧栏已移除但标签仍留在编辑器，初始工具 AX 返回“已保存”；稍后的截图出现磁盘删除警告。这个别名差异还会漏过操作前的脏文档检查。

修复在文件操作开始后、保存检查前，通过受窗口 IPC 权限保护的 `resolveDocumentPaths` 统一已授权文档的父目录路径。保留叶文件名，不把文件符号链接直接解引用；继续由原有文件操作边界检查拒绝危险目标。旧会话路径也参与处理；路径调整保留编辑内容、dirty 和 diskVersion。授权/目录归属/最近路径一起迁移，持久化失败则回滚。保存失败继续阻止废纸篓操作。

没有全局修改打开/保存 API 的返回路径：最初尝试导致 7 个既有授权/路径回归失败，日志保留在 `desktop-initial-failure.log`；调整为文件操作前统一身份后全部通过。

2. `finder-recovery.json`：Finder 确认自建副本位于废纸篓。其“放回原处”实际为 disabled，使用 Finder 复制并在原目录 Cmd+Option+V 移回，读回原文字。未清空废纸篓或操作其他项目，没有宣称自动放回可用。
3. `02-trash-tab-closed.png` / `.ax.txt`：最终 QA 包恢复旧会话后，为该副本追加“第五轮：移入废纸篓前保存这段编辑。”，确认移入废纸篓。对应标签已关闭，切换到其他文档。
4. `recovered-copy.md`：再次通过 Finder 移回后直接读取的自建样本，包含最新编辑，证明先保存再移入废纸篓；原件 `readonly.md` 和仓库上传 fixture 未修改。
5. `verification.json`：最终 asar 摘要，三个 Electron 源文件与包内逐字节一致，QA 元数据为 true。未签名包只用于本机隔离配置，没有覆盖 Applications 或发布版本。
