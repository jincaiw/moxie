# 第四轮：macOS 只读保存验收（2026-10-11）

## 发现与修复

临时目录中的 `readonly.md` 为 `0444`，父目录可写。修复前 `FileStore.save` 原子重命名仍会替换原件，CLI 已复现；随后只恢复了自建临时样本。修复在创建临时文件前及重命名前检查现有目标的 POSIX 写入位和当前进程的 W_OK 权限；错误保留编辑内容并提示另存为。新副本仍可保存，临时文件在失败后清理。

54 项桌面测试全部通过，新增真实文件系统用例覆盖手动保存、自动保存、同路径另存为、新路径副本和写入途中权限变化。固定 QA 命令构建、打包成功；本轮没有修改渲染器，也没有重跑第三轮界面或性能测试。

1. `01-readonly-rejected.png` / `.ax.txt`：Cmd+S 被拒绝后的未保存编辑状态。短暂错误提示已在截图前消失；首次 CUA AX 返回的准确错误文本记录在 `filesystem-verification.json`，不能把截图当作提示文字证据。

4. `verification.json`、`desktop-tests.log`、`package-qa.log`：源码/包/原件摘要和验证记录。未签名 QA 包使用独立配置目录，没有安装到 Applications。

## 边界

本轮没有对 Typora 的同类权限行为作新结论；修复依据是墨写实际绕过文件只读位的问题。POSIX 模式位和 W_OK 检查不等于消除所有检查与替换间的竞态，也不证明 Windows 只读属性、ACL、不可变标记、磁盘已满、缺失目录、系统废纸篓或打印验收通过。界面仍显示 Electron 的 IPC 错误前缀，是后续错误文案整理项。临时样本只位于工具记录中的自建临时目录，未改用户文档或上传原件。
